## Implementation and initial evidence gaps

There was no auth module, schema, OTP client or session proof. The initial focused test failed on the missing module. The implementation now uses Better Auth directly against the D1 binding; migration `0003-auth-session-proof.sql` creates its canonical tables. No JWT/session substitute or mocked D1 adapter was introduced.

Web uses HttpOnly cookies. Native uses the Expo plugin with SecureStore, forwards its cookie with `credentials: omit`, and supplies the exact temporary application origin. Every protected request resolves the canonical D1 session with cookie cache disabled. A native cached user/session object cannot grant access.

OTP lifetime is 300 seconds; wrong-attempt allowance is three; sends are limited to ten per 60 seconds with D1-backed rate-limit state. Codes are hashed in D1. The proof only exposes email sign-in, session lookup and sign-out. Foreign origins/redirects and unused auth endpoints are rejected. Recipient filtering returns the same send response for existing, new and unapproved accounts without sending to unapproved addresses.

## Findings and limits

1. Disabling code signing allowed the iOS app to launch but caused SecureStore error -34018: no application-identifier/keychain entitlement. Keeping normal simulator ad hoc signing fixed it. The final Release build uses simulated application entitlements; storage was not weakened. The prevention rule is recorded in `apps/app/AGENTS.md`.
2. Android API 37 did not finish booting. A fresh, isolated `Cookbook_T07_API35` AVD using the official Google APIs arm64 image booted and ran the final Release APK. Existing unrelated AVDs were not modified.
3. Loopback HTTP is confined to this proof. HTTPS cookie flags are asserted in the D1 integration test; the local browser proof uses HttpOnly/SameSite cookies over loopback. Android cleartext support and the test mailbox/control route must not ship. Production HTTPS origins, distribution/signing and platform-version coverage remain later release work.
4. The local driver can revoke/reset only its isolated test database. Its controls and fixed header are not an authorization design. Never deploy the driver. Reports and result screenshots omit OTP values, session tokens and cookies; web traces/video are disabled.
5. Native restarts preserve credentials while the server and its signing secret remain stable. Backend-instance recreation with the same secret is separately covered by the D1 test. Persist the signing secret in managed configuration for deployment.
6. T03 physical-device pending-shopping acceptance remains blocked; T07 does not close it, T43, accessibility evaluation, household authorization, production mail monitoring or either readiness gate. T08/T10/T24/T35 must consume the session contract in the runbook rather than trust client cache or email identifiers.
