## Implementation and hosting boundary

- `apps/app/src/shopping/pending-state.ts` contains the shared transitions and queue interface used by SQLite and IndexedDB. `sync-state.ts` accepts that interface and retains the captured-identity dispatch/acknowledgment fences.
- `pending.web.ts` stores rows in IndexedDB, keyed by account, household, immutable list and item ID. Read/write transactions serialize concurrent connections. Strict durability is requested; successful requests do not acknowledge a save until the transaction emits `complete`. Aborts and storage errors reject the action. There is no volatile fallback.
- Pending and in-flight commands stay separate. Unknown delivery retries the original ID and revision. Snapshot refresh cannot clear either command. Terminal acknowledgments match the in-flight ID; removed items retain tombstones. Logout clears all queues of the current account, while revocation clears only its household.
- `apps/app/src/proof/shopping-screen.web.tsx` is temporary, synthetic UI. It confirms local saving only after commit and exposes failures. The fixture transport is intercepted by Playwright; it is not authentication or a deployed mutation endpoint.
- `apps/api/wrangler.web-proof.jsonc` serves the exported Expo shell through **local Worker assets**, bound to `127.0.0.1:8788`. `/proof-shopping` loads directly with HTTP 200. There are no D1 bindings, production routes, public preview URLs or deployment in this proof.

The first web export exposed a platform-boundary error: Expo Router enumerated the base route containing a native SQLite import. Moving both screen implementations outside `app/` and importing their shared basename from a thin route fixed the export. The prevention rule is recorded in `apps/app/AGENTS.md`. Native UI behavior is unchanged; native automated tests and both Metro exports passed after the move. Earlier T03 binary hashes remain historical evidence for their original build, not this source revision.

## Reproduction

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install --with-deps chromium webkit
pnpm test:app tests/shopping/pending.web.test.ts
pnpm test:web tests/web/offline-proof.spec.ts
pnpm check
```

`pnpm test:web` builds the static shell, starts the local Wrangler assets server and stops it when finished. JSON results are written to `test-results/web-results.json`; traces/screenshots are retained for failures. The restart test closes and relaunches `launchPersistentContext` with the same isolated directory; it does not reconstruct storage from `storageState`.

## Limits and handoff

- The offline reload test supplies the previously fetched HTML/JS/assets from an in-memory **test harness** while the browser is offline. It proves pending persistence when the app can load. No service worker, offline cold-start support or production cache policy is implemented or promised.
- Permission and quota failures are deliberately injected at the IndexedDB API boundary. The transaction-abort case uses a real browser transaction and aborts after its successful request event. These are deterministic failure-path tests, not physical disk exhaustion or permission-setting coverage.
- Restart means closing and relaunching the actual browser process. Power loss, browser eviction, user-cleared site data and private-mode retention are not established by this proof. IndexedDB remains origin-scoped browser storage.
- T07/T24 must supply real credentials bound to captured identity, server authorization, production list snapshots and lifecycle triggers. Map `Command.revision` to T01 `expectedRevision`; use the proven store rather than rewriting it. Remove the fixture screen and transport when integrating. T24 remains blocked by its other dependencies, including T03.
- Physical iOS/Android airplane-mode, force-close and reconnect trials remain missing. **T03 is still blocked.** Browser engine tests do not replace those trials.
