## Contract implemented

- `usage/reservations.ts`: atomically creates one logical job and its reservation. The capacity predicate counts both reserved and consumed units; concurrent last-unit requests cannot oversubscribe. Reusing an operation ID with changed intent fails. Inputs for identity, window and units must come from trusted server policy.
- `imports/reconcile-dispatch.ts`: discovers pending jobs from D1 and publishes their ID/generation. Failed or uncertain sends leave discoverable work. A confirmed send is revisited after the dispatch deadline if no consumer started. Concurrent reconcilers may publish duplicates; correctness does not depend on exactly-once delivery.
- `imports/job-state.ts`: claims a job with a persisted token and lease, limiting processing to three attempts per generation. Expired leases are recoverable. An older worker cannot settle after its token is replaced. Repeated crashes eventually produce terminal failure and release capacity through reconciliation.
- Settlement updates job state, publishes one result and consumes/releases the reservation in the same D1 batch. Membership and source availability are rechecked inside the terminal update, after external processing. `changes()` gates result insertion on winning that transition. Failure of result insertion rolls back the job transition and accounting.
- Terminal failures release once. An explicit user retry reacquires capacity for the same logical job, increases its generation and rejects old-generation messages. Concurrent retry requests create one retry generation. If another operation took the released capacity, retry stays failed until capacity is available. Successful or canceled jobs cannot be restarted by retry.
- `proofs/t05-worker.ts` is an isolated test entry point, with synthetic results and controlled enqueue/processing/acknowledgment failures. It is not a production import route.

## Limits and downstream integration

- This proves accounting and publication, not model quality, real audio/image processing or R2 backup deletion. Sources are synthetic D1 records; processors never recreate them. T15/T16/T19/T35 must extend the authorization/deletion fence to actual private media and cleanup inventories.
- Worker-crash tests abandon a persisted lease and advance the supplied clock. Lost-ack tests explicitly request real Queue redelivery after settlement. These are controlled faults, not a provider outage or physical crash of Cloudflare infrastructure.
- Three processing attempts and a 60-second lease are proof parameters, not accepted model latency/retry policy. T09/T16/T19 must set bounded processor timeouts and lease/recovery policy from measured workloads. Overlapping expired work may incur provider compute; only the result and household allowance settlement are deduplicated.
- T28 owns actual allowance categories, calendar windows and entitlements. It must reuse this atomic reservation core and supply immutable server-owned operation intent. T16/T19 must connect authenticated requests, explicit retry UI, scheduled reconciliation and operational alerts. No live recurring schedule was left running by the proof.
- T03 still lacks physical iOS/Android airplane-mode, termination and reconnect evidence. T05 does not close that blocker.
